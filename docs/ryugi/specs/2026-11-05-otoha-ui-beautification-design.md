# Otoha UI 美化方案

日期：2026-11-05。基线：`main` / `39d3c8f`，已合并共享主题变量规范。

状态更新（2026-11-12）：产品实现与真实 IINA 界面验收已完成，后续生成完成动效也已实机验证；实现与验证记录见 [PR #38](https://github.com/BBboy01/otoha/pull/38)。VoiceOver 完整听读仍待确认。本文保留设计时点的目标与评审记录，当前布局、功能和实机图片/视频以[项目 README](../../../README.md#界面预览)为准，实际样式值以[共享主题变量](../../ui-theme.md)为准。

## 1. 推荐方向

**品牌化字幕面板：让 Otoha 拥有可识别的视觉语言。**

评审意见：“不考虑成本，这是一个很值得做的方向。”据此将品牌化由备选提升为设计主线。实现成本不作为否决理由；窄栏可用性、内容可读性和宿主兼容性是需要解决的设计要求。

已确认的效果稿方向为“字幕的双行关系”：石墨色与白色表面、青绿色品牌强调、原文与译文的成对排版。系统字体、键盘习惯和控件语义继续沿用 macOS；品牌识别体现在整个工作区，而非仅替换按钮颜色。

| 方向 | 特点 | 取舍 |
| --- | --- | --- |
| 原生精修 | macOS 字体与控件，中性表面 | 作为交互与可读性基础 |
| 字幕工作台 | 片段列表、时间信息和工具栏 | 提供字幕领域的内容组织方式 |
| 品牌化面板，主方向 | 独立配色、品牌标题、成对原译排版、统一状态视觉 | 值得完整设计；窄栏适配与宿主协调纳入验收 |

本期以品牌化字幕工作台为主线，结合原生操作习惯和字幕领域结构；不把它们当作互斥选项。第二条评审意见：“大胆改造，插件还处于快速开发迭代。”因此允许重新组织页面与替换展示控件，不把现有 DOM、原生列表或当前交互布局作为设计上限。

### 1.1 设计依据与识别特征

- **产品**：用户在观看视频时生成、选择、校对字幕，界面应让语言内容与当前状态易于辨认。
- **性格**：专注、细腻、有节奏。通过稳定的数字、文本层级和重复对齐表达。
- **领域**：双语字幕与片段时间，而非聊天机器人或音频均衡器；不绘制虚构波形和时间线。
- **重点**：首页的当前字幕与校对页的原译文编辑，是视觉丰富度集中的两处。
- **识别细节**：原文与译文共用对齐轴；原文用中性标记，译文用青绿色短线。语言摘要、编辑标签和导出选项复用这一关系，标签始终保留，颜色不单独承担语义。

标题使用 Otoha 文字标识和紧凑语言关系，不新增大号品牌横幅。短线属于标签分组细节，不围出卡片，也不贯穿所有区块。页面更换产品名后，仍应通过原译成对结构辨认出字幕工具。

用户已确认按原译成对、石墨与青绿制作效果稿。方向确认覆盖效果稿制作；具体色值、标题处理和控件细节通过首页、生成中和校对页的深浅色效果稿评审，再进入产品实现。

## 2. 现状与目标

当前原生截图和 HTML/CSS 显示：各区块标题、分隔线、表单权重接近；大面积蓝色“校对字幕”压过字幕内容；元数据较碎；控件高度和间距保留了一批历史值。深浅色主题基础已经具备，但尚未形成明确的视觉层级。

设计目标：

- 一眼识别当前视频、当前字幕、当前任务；低频设置靠后。
- 同类控件拥有一致的高度、图标、字体和状态；间距及尺寸通过主题变量调整。
- 210px 窄侧栏仍可操作，420px 侧栏更舒展；长名称、错误和多语言内容不会撑破布局。
- 深浅色主题均有层次，键盘焦点、错误和加载状态清楚可见。
- 标题、表面、语言摘要、原译文和状态拥有统一的品牌表达，成对排版体现字幕产品特征。

IINA 的窗口标题栏、侧栏标签、窗口材质由宿主负责。美化范围是插件内容区，不承诺修改宿主界面。

## 3. 页面组织

首页重组为以下四层；进入校对后使用独立工作区，不把所有内容堆在一个表单中：

1. **上下文区**：Otoha 标识、Apple 本机说明、当前视频。
2. **字幕工作区**：字幕选择、加载状态、校对、导出、更多操作。
3. **生成区**：音轨、语言组合、资源检查、生成操作和任务反馈。
4. **播放区**：自动加载、字幕显示方式。

无字幕时展开生成区；有字幕时沿用现有折叠规则。任务进行中保持必要反馈可见，不因折叠丢失停止入口。返回校对前的侧栏时恢复合理位置，避免重复渲染造成跳动。

全局路径、默认语言、字幕字号仍在设置页。自动加载仍只加载已有字幕，不隐式启动生成。

## 4. 主题变量体系

沿用 `plugin/theme.css` 与 `docs/ui-theme.md`，采用“基础变量 → 语义变量 → 组件消费”的单向关系。颜色、字号、间距、圆角、尺寸、阴影和动效值集中定义；组件样式引用变量，不重新写一套数字。

只有被重复使用或具有独立语义的值才新增变量，避免每个选择器都拥有专用 token。局部设置页覆盖语义变量，不能反向修改全局基础比例。

### 4.1 间距与尺寸

以现有 4px 基础单位为主，2px 用于光学校准；下表中的名字均带 `--otoha-` 前缀。

| 变量后缀 | 当前 | 建议目标 | 用途 |
| --- | --- | --- | --- |
| `space-action-gap` | 3px | `space-1` / 4px | 同组紧邻操作 |
| `space-label-gap` | 5px | `space-1` / 4px | 标签到控件 |
| `space-row-gap` | 7px | `space-2` / 8px | 同组字段行 |
| `space-section-inset` | 11px | `space-3` / 12px | 区块内容内距 |
| `sidebar-padding-top` | 13px | `space-4` / 16px | 顶部呼吸空间 |
| `space-section-gap` | 15px | `space-4` / 16px | 独立区块间距 |
| `sidebar-padding-inline` | 12px | 常规 16px，窄栏 12px | 页面边距 |
| `dialog-padding` | 14px | `space-4` / 16px | 弹窗内距 |
| `control-height` | 31px | 32px | 表单与普通按钮 |
| `control-height-primary` | 34px | 36px | 生成与关键提交 |
| `control-size` | 32px | 32px | 导出、更多、关闭等图标按钮 |
| `icon-size` | 16px | 16px | 工具图标 |
| `radius-control` | 5px | 6px | 控件与菜单选中行 |
| `radius-dialog` | 6px | 8px | 模态弹窗 |
| `menu-width` | 190px | 208px，受可用宽度约束 | 更多操作菜单 |

工具栏按钮之间使用 `space-2`，紧邻的图标与文字使用 `space-1-5`，与“同组紧邻操作”区分。导出选项组到提交按钮固定使用 `space-3`，保留已经修复的 12px 间隔。

最小侧栏宽度保持 210px。窄栏规则沿用 280px 边界，所有受宽度影响的组件同步使用这一规则；菜单和弹窗不能只设置理想宽度，还需限制在视口内。媒体查询条件保留显式数字并注释用途，因为原生 CSS 不能直接用自定义属性作为媒体查询条件；不为此引入构建工具。

### 4.2 字体

| 层级 | 建议规格 | 使用位置 |
| --- | --- | --- |
| 页面标题 | 16px / 600 / 1.25 | Otoha、校对页标题、弹窗标题 |
| 区块标题 | 12px / 600 / 1.4 | 当前字幕、生成字幕、播放 |
| 正文与控件 | 13px / 400 / 1.45 | 输入、选项、字幕文本、操作 |
| 辅助信息 | 12px / 400 / 1.4 | 文件详情、语言资源、说明 |
| 紧凑元数据 | 11px / 400 / 1.4 | 版本、耗时、时间范围 |

保持系统字体和零字间距，不按视口宽度缩放字号。9px/10px 不再用于承载关键正文；帮助符号等图形用途单独处理。时间、数量、百分比使用等宽数字特性，减少更新抖动。路径和字幕正文可选择复制。

### 4.3 颜色与表面

继续支持自动深浅色，在现有语义变量上定义品牌表面与强调色，而不是把当前系统灰和蓝色视为不可更改的约束。以下为候选值；系统强制颜色模式回退至 `Canvas`、`Field`、`CanvasText`、`Highlight` 等系统颜色。

| 语义 | 推荐定义 | 规则 |
| --- | --- | --- |
| 页面背景 | `color-surface`：浅色 `#f7f8f8`，深色 `#202223` | 中性白与石墨色，全宽平面布局 |
| 输入背景 | `color-field`：浅色 `#ffffff`，深色 `#292c2d` | 输入与可编辑内容的边界清楚 |
| 弱背景 | `color-surface-inset`，从品牌表面推导 | 轻量区分只读信息或任务区域 |
| 操作强调 | `color-accent`：浅色 `#0f766e`，深色 `#5ed6c3` | 品牌识别、主要提交、选中态、焦点 |
| 强调色上文字 | `color-on-accent`：浅色 `#ffffff`，深色 `#102b27` | 深色主题不沿用白色按钮字 |
| 正文 | `color-text`：浅色 `#202628`，深色 `#eef1f1` | 中性底色，不把正文染成品牌色 |
| 弱强调背景 | 新增 `color-accent-subtle`，由强调色与表面混合 | 选中内容与轻量反馈 |
| 成功 | 新增 `color-success`：浅色建议 `#267a45`，深色建议 `#86d99c` | 与勾选图标、文字同时出现 |
| 警告与错误 | 沿用现有浅深色语义变量 | 不仅靠颜色区分 |
| 边线 | 区块边线弱、交互控件边界更明确 | 减少重复分隔线 |
| 悬浮表面 | 菜单与弹窗使用适配深浅色的阴影、边线 | 普通页面区块不加投影 |

品牌色文本与按钮背景使用独立语义值，悬停、按下及选中分别适配深浅色。正文和辅助文字以实际合成背景计算对比度，目标至少 4.5:1；识别控件所必需的边界及焦点至少 3:1。成功色与青绿品牌色不承担相同含义，必须通过状态文字和勾选图标区分。候选色须实测后确定，不能仅凭混合百分比判断。

品牌强调集中在标题细节、语言关系、选中内容和主要操作；其余空间由中性表面、正文、成功绿及警告/错误语义色共同组成。普通区块保持平面分组。品牌探索不受当前样式和实现成本限制，视觉取舍以字幕可读性、识别度与实际内容空间为依据。

### 4.4 状态与动效

新增共享动效语义变量，建议快速反馈 120ms、普通切换 160ms；仅用于颜色、透明度和轻量状态反馈。避免区块高度动画和按钮缩放造成跳动。减少动态效果模式关闭非必要动画。

保留 2px 焦点环及 2px 偏移；悬停、按下、焦点、选中、禁用分别定义。禁用态不能使说明文字无法阅读，不能仅用降低整个区块透明度的方式表达忙碌。图标按钮默认 32px 命中区，图形 16px；窄栏也不缩小关闭、导出、更多等高频入口。

## 5. 侧栏首页

### 上下文区

Otoha 作为紧凑文字标识保持第一眼可见，配合与原译分组一致的短线细节；“Apple 本机”作为低权重说明，不做徽章堆叠。当前视频名称独立占一行，最多两行，避免与标签争抢横向空间。长文件名截断仅限概览位置，完整名称保留可访问名称与详情入口。

标题下不必增加额外口号、使用教学或功能描述。上下文区与字幕工作区靠 16px 留白区分，去掉没有分组价值的重复横线。

### 字幕工作区

字幕区改为可展开的“当前字幕选择器”：收起时以语言组合为主行、版本与加载状态为次行；展开后显示各版本及选中标记。语言顺序始终为“源语言 → 目标语言”。选项仅承担选择，不内嵌删除、导出等按钮。采用单选 listbox 语义，支持箭头、Home/End 定位，Enter/Space 提交选择，Escape 关闭，焦点回到触发器；继续调用现有字幕选择逻辑。已加载状态保留勾选和可读名称，与“当前选中”明确区分。

“文件详情”保持低权重披露，文件名和路径在展开后换行。主操作行采用“校对字幕 + 导出图标 + 更多图标”，三者等高。**已有字幕时，校对按钮改为中性描边或浅填充**，让当前字幕本身更突出；生成区中的提交仍使用强调色。

更多菜单统一图标列、文字列、13px 字号和行高；两条操作同样对齐。“删除字幕”保持单行且不附省略号，危险色只用于这一项及最终确认。菜单向可用空间展开，210px 视口不越界，不通过缩小字号解决长度问题。

### 播放区

自动加载保留复选框语义和现有帮助入口。字幕显示方式改为“原文 / 译文 / 双语”三段式单选，使用原生 radio 与 label 实现统一外观；Tab 进入一组、方向键切换、Space 选择。三个选项等分可用宽度，210px 下完整可读；选中态同时使用边界与底色。沿用现有显示模式消息与忙碌禁用条件。播放区放在内容末尾，视觉权重低于字幕工作区。

## 6. 生成与任务状态

音轨独占一行，源语言和目标语言在空间足够时并列；窄栏改为纵向排列。语言关系通过标签与排列顺序表达，不添加抢占空间的独立装饰箭头。

资源检查紧贴语言字段；优先显示结论，语音资源与翻译资源分开描述，具体原因按需展开。生成按钮保留强调色，文字采用现有行为对应的“生成”或“生成新版本”。

任务反馈使用完整宽度的轻量状态区域，以图标、标题、次级信息和操作组织，不再叠加另一张卡片。进行中反馈位置稳定；无任务时允许隐藏，不预留大片空白。

| 状态 | 视觉与信息 | 操作约束 |
| --- | --- | --- |
| 未打开视频 | 简短中性空态 | 沿用现有禁用条件 |
| 无字幕 | 生成区展开，突出语言与生成 | 不自动开始任务 |
| 检查中 | 文字及轻量忙碌指示 | 不显示未经确认的可用状态 |
| 资源缺失 | 警告图标、缺失项、现有下载说明 | 保留现有重新检查入口 |
| 转写中 | 当前阶段、真实耗时、不定进度 | 停止入口持续可见 |
| 翻译中 | 真实已完成量或真实进度 | 不模拟百分比 |
| 正在停止 | 明确“正在停止” | 不提前恢复生成与删除 |
| 已生成，加载中 | 区分生成完成与播放加载 | 按完整任务生命周期禁用 |
| 已生成并加载 | 简短成功反馈，更新字幕状态 | 复用现有校对入口 |
| 已生成，加载失败 | 清楚说明文件仍已生成 | 仅使用现有加载重试路径 |
| 未识别到语音 | 中性结果与已有解释 | 不伪装为成功字幕或通用故障 |
| 失败 | 错误摘要、可展开详情 | 只展示当前控制器支持的恢复操作 |

任务终态事件到达后，Helper 可能尚未退出；`jobActive` 仍是禁用依据。视觉改造不得只看状态标题就重新启用操作。耗时取现有主进程时间戳，不另外创建独立任务计时真相。

## 7. 校对页

校对是本次最值得细化的工作区，目标是“片段定位清楚、原译关系清楚、保存状态清楚”。

- **顶部**：返回图标与“校对字幕”同一行；文件名次级显示，计数和状态不要与标题抢权重。
- **片段区**：将原生 `select size="6"` 替换为可访问片段 listbox；每行展示序号/时间、原文预览、译文预览，未保存片段有文字标记。选中行用弱强调背景与侧边标记，不形成独立卡片。默认行最小高度建议 72px，由新语义变量定义，文本放大时可增长；预览各最多一行，完整文本在编辑区可读。
- **编辑区**：原文在上、译文在下，共用文本对齐轴；标签旁分别使用中性与青绿色短线，译文区域使用轻量强调背景。两组清楚可辨、对齐统一，不新增左右分栏。原文仍可编辑，不能因美化变成只读。
- **底部**：采用稳定保存工具栏，状态在上、操作在下；“保存”为次要操作，“保存并下一句”为主要操作。工具栏与内容区占独立布局轨道，避免覆盖最后一行、错误或焦点环；窄栏按钮可纵排。
- **反馈**：正在保存、保存成功、失败各有清晰文本；不因计时消息、数量更新反复抢焦点。

低高度时先压缩片段列表和文本区，再让内容滚动；保留保存操作可达。不得改变既有草稿、切句、保存失败、跨视频分离、未保存确认及最后一句禁用逻辑。

片段列表采用单选语义与 roving tabindex：Tab 进入当前片段，上下箭头/Home/End 切句并更新编辑区，列表保留焦点；Enter 进入原文编辑。鼠标选句不自动跳转播放，跳转仍由独立按钮触发。切句前写回现有草稿，未保存标记来自草稿与 baseline 比较；保存中列表及相关操作一并禁用。选中行在列表滚动容器内保持可见，不滚动整个页面或重建编辑器焦点。

210/260px 使用“片段列表 → 原译编辑 → 保存工具栏”纵向结构；420px 仍保留纵向结构，增加可读空间。低高度优先缩短列表视区，编辑内容滚动，工具栏保留独立位置。长列表先使用普通滚动，实测性能后再决定是否虚拟化；不得牺牲辅助技术可达性。自制列表是本轮方案目标，不再放到假定的高级版本；搜索、时间轴、时间码编辑仍是新增产品能力，另行讨论。

## 8. 弹窗与更多操作

统一弹窗标题、关闭按钮、正文宽度、16px 内距、8px 圆角和按钮行。按现有不同宽度语义变量设置理想尺寸，最终宽度必须受当前插件视口限制；长内容可滚动。

| 场景 | 设计要点 | 必须保留的行为 |
| --- | --- | --- |
| 导出 SRT | 原文/译文/双语为一个紧凑选项组；到导出按钮至少 12px；结果独立留白 | 使用原生 radio，导出中禁用既有相关操作，成功后可在 Finder 显示 |
| 删除字幕 | 标题、对象、影响说明、取消/删除；危险色集中在最终操作 | 默认焦点取消；删除中沿用禁止重复提交和关闭的规则；失败留在弹窗 |
| 生成新版本 | 明确复用现有覆盖说明，按钮文字精确 | 默认取消，不弱化覆盖风险 |
| 放弃修改 | 继续校对为安全操作，放弃修改明确可辨 | Escape 与现有安全退出规则一致，关闭后焦点恢复 |

SRT 是从规范 ASS 派生的导出副本，仍写入字幕库 `Exports`。不将系统目录选择器加入此美化范围，不修改输出路径、字幕生成或文件覆盖语义。

## 9. 设置页

保留现有“语言偏好、FFmpeg、字幕库、播放、字幕样式”顺序，采用平面分组与统一留白，不使用层层卡片。

宽度充足时可用左标签、右字段的两列布局；标签列新增语义变量，建议 128px，字段列 `minmax(0, 1fr)`。窄窗口降为标签在上、控件在下。最大内容宽度保留 720px。输入、选择、滑块采用统一字体和高度。

路径输入占满可用宽度，帮助文字可换行；字号滑块的数值列稳定，避免从 90% 变成 100% 时挤动布局。不引入主题配置面板、品牌色选择器或额外设置保存流程。

## 10. 响应式与无障碍

| 情况 | 处理 |
| --- | --- |
| 210px 最小侧栏 | 边距 12px；语言字段纵排；操作行和菜单完整可用 |
| 260px 常见窄栏 | 保持紧凑层级，长标签允许换行 |
| 420px 较宽侧栏 | 边距 16px；相关字段可并列，正文不放大 |
| 低于或等于 600px 高度 | 沿用紧凑校对模式，确认滚动与保存区可达 |
| 长中英文、日文、路径 | 概览可截断；正文、错误、详情可换行，不丢完整信息 |
| 放大文本 | 文字控件用最小高度而非刚性裁切；必要时改纵向布局 |

DOM 阅读顺序与视觉顺序一致。button、input、dialog 等优先使用原生元素；新字幕选择器和片段列表补齐单选 listbox、焦点与键盘语义。所有图标操作有可访问名称及悬停/键盘可见提示；不把悬停设为唯一入口。弹窗限制焦点、关闭后返回合理触发点；删空字幕时沿用现有回退焦点。

任务区域使用既有 live region，阶段变化才播报，避免每秒耗时触发重复朗读。错误关联具体字段；保存、加载和删除状态不能只用图标表达。装饰图标不重复朗读。

## 11. 实现边界与文件归属

| 模块 | 预计改动 | 边界 |
| --- | --- | --- |
| `plugin/theme.css`、`docs/ui-theme.md` | 语义变量及规范目标值 | 保持变量命名与入口契约 |
| `plugin/sidebar.css`、`sidebar.html`、对应视图 JS | 重组首页、字幕选择器、三段切换与工具栏 | 同步更新绑定及测试，不复制任务状态 |
| `sidebar-workflow.css` | 表单、资源与生成区域 | 展开/折叠遵守已有状态 |
| `subtitle-editor.css`、`subtitle-editor.js`、编辑器视图结构 | 片段 listbox、校对布局、滚动及保存工具栏 | 复用现有草稿与保存模型 |
| `subtitle-export.css`、`sidebar-deletion.css` | 弹窗与菜单一致性 | 保留既有确认与执行中策略 |
| `plugin/preferences.css`、`preferences.html` | 设置排版与帮助文字 | 不新增全局选项 |
| 对应视图 JS 和聚焦测试 | 覆盖选择器、radio、listbox、焦点与禁用行为 | 不创建新的任务状态来源 |

`runtime-store` 继续提供规范 AppState，主控制器继续管理 Helper 与媒体。视觉方案不修改 Swift Helper、IPC 协议、字幕格式、资源检测、视频切换或导出语义。不为这轮引入组件框架、CSS 预处理器或通用设计系统依赖。若 DOM 调整触及交互，按实际影响补聚焦测试，不能宣称全是 CSS 改动。

## 12. 实施顺序

先完成品牌效果稿，再按三个产品阶段落地。每阶段独立 PR、独立可回退；分期用于评审与验证，不代表降低最终视觉目标。

**效果稿准备**：展示首页、生成中、校对页的深浅色外观，并覆盖 260/420px；首页另验 210px。明确品牌标题、青绿强调、原译成对关系、新字幕选择器、三段切换、片段列表与菜单状态。效果稿标注为设计预览，不能充当真实 IINA 的实现对比图。整体规模为跨页面的 UI/UX 改造，包含视图交互和测试，不再按主题换肤估计工作。

1. **基础与侧栏**：更新主题目标值，完成上下文、字幕操作、更多菜单、播放区；解决常见深浅色和窄栏表现。产出首页与菜单实机前后对比。
2. **生成与状态**：整理生成表单、资源检查、任务阶段和错误详情；核验 busy、canceling、load-error 等状态。产出空态、进行中、缺失资源和失败对比。
3. **校对、弹窗与设置**：完成校对排版、滚动、保存区、四类弹窗和设置页；验证焦点与执行中保护。产出校对、导出、删除、设置前后对比。

先完成第一阶段的真实 IINA 视觉检查，再沿批准的品牌视觉体系推进后续阶段。品牌识别同时覆盖标题、表面、内容结构与交互反馈，不能在实现时退化成只换强调色。

## 13. 验收与交付

以下是实施后的验收要求，本轮仅做方案，尚未执行这些新样式检查。

- **主题契约**：检查所有消费变量有定义、两入口加载顺序、打包清单；只对修改文件运行适用的格式、语法和样式检查。
- **浏览器矩阵**：首页、更多菜单、生成、资源缺失、任务进行中/停止/失败、校对、导出、删除、设置；深浅色 × 260/420px。额外覆盖 210px 极窄、600px 低高、200% 文本放大、长路径及多语言内容。
- **行为回归**：按修改范围运行现有聚焦测试；视图 DOM 或 JS 有变化时覆盖按钮绑定、禁用条件、焦点返回、保存失败和状态更新，不只断言 CSS 字符串。
- **真实 IINA**：确认插件实际加载最新文件；验证深浅色、菜单边界、原生 select/checkbox/radio/dialog、滚动和字体。浏览器截图不能替代原生验收。
- **键盘与 VoiceOver**：Tab 顺序、焦点可见、弹窗进入退出、源/目标语言字段、片段选择、保存区及任务播报；在后台截图与检查完成后，仅在必要交互时短暂聚焦，并恢复前台与设置。
- **截图交付**：每个涉及 UI/UX 的 PR 描述附真实 IINA 前后图，标注相同窗口尺寸、主题、媒体与状态。图作为 PR 附件，不进入仓库；新阶段只更新自己的未合并 PR。
- **状态透明**：真实 Helper 或系统资源导致未验收时，单独写明；不把模拟任务或浏览器预览写成实机端到端通过。

原生操作优先用 `agent-desktop` 的非激活能力。截图与读取状态不主动聚焦；只有键盘/VoiceOver 等确需前台的动作才短暂激活。不能为了截图美观跳过执行中状态或改动用户已有工作。

完成标准：无溢出、重叠、菜单异常换行、按钮字体不一致；关键操作尺寸一致；状态和恢复入口明确；主题可通过少数语义变量调整；真实 IINA 与键盘检查有证据。

回退采用按阶段 revert；共享变量和相应组件消费在同一阶段回退，不让新旧间距规则混用。截图保留为 PR 证据，临时验证数据不进入产品或仓库。

## 14. 方案结论与待确认范围

按评审意见，将**品牌化字幕面板**作为主方向，不以实现成本排除值得做的设计。建议采用石墨/白色表面、青绿强调、紧凑 Otoha 文字标识，以及贯穿语言摘要和校对区的原译成对关系。

用户已明确品牌化值得推进并鼓励大胆改造，且已提交“按原译成对、石墨与青绿出效果稿”的选择。方案纳入新字幕选择器、三段显示切换、双语片段列表与独立保存工具栏，允许调整 DOM 与视图 JS。上述设计已进入产品实现并完成界面验收，当前交互以[产品与技术决策](../../iina-transcription-translation-plugin-plan.md)及 README 实机素材为准。搜索、时间轴等新增能力仍单独讨论。实现成本不再是本方案的方向筛选条件。
